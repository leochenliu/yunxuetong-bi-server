## 新建项目 yunxuetong-bi-server（云学通 BI 差分与事实服务）

技术栈：Python 3.13 + FastAPI + SQLite + FastMCP 4.1（用户选定）。交付形态：后端 + 轻量 Web 对话页。

### 数据来源（关键事实）
- 真实 D1：`C:/Users/leoch/Downloads/(登高)总表.xlsx`（= `20261012` 基线）**905 行 / 883 人**（剔除 22 行无证件号，占 2.4%）。
- 该项目与既有 `trainingos-webhook-events/excel-cockpit`（TypeScript 原型）同源，差分的口径/字段/主键**全部沿用其已验证设计**。
- `Downloads/(登高)总表 (1).xlsx` 只有 5 行，是碎片，**不能**当第二期。
- 因此 D2（20261013）由 `src/bi/simulate.py` 从真实 D1 派生，生成时记录 ground truth。

### 五阶段交付
1. **Excel 差分**：主键 `证件号码|姓名` 复合键（实测存在同证件号不同名的两人，裸证件号会静默覆盖）；追踪 6 个状态字段（开班编号/考试状态/考试日期/分数/是否付款/备注1）；派生列 `报名日期` 由开班编号解析（`0706782`+年份位+MMDD+班序号，13 位）；异常规则 9 条。
2. **事实存储**：SQLite 6 张表（upload_versions / raw_records / diff_events / metric_snapshots / anomalies / audit_log）。
3. **固定查询 API**：`/metrics/compare`（含归因 residual）、`/diffs/summary`、`/diffs/records`、`/evidence/{id}`。
4. **MCP**：6 个只读工具，limit 硬上限 + 参数白名单 + 全量审计；MCP 走 HTTP API（复用已测实现）。
5. **Agent**：13 步自适应闭环（下钻与证据追溯由前一步结果条件触发），可选 LLM。

### 验证结果
- **61 个测试全部通过**；`scripts/acceptance.py` 五阶段全跑通，与 ground truth 逐条对账一致。
- 核心数字：883 → 887 人；新增 12 / 移除 8 / 变更 111 人（201 字段级事件）/ 未变 764。
- **所有可计数指标的归因残差均为 0**（已完全解释）。
- 真实数据首轮检出业务异常：**3 人「考试状态=已通过」但无分数**（卢华波、黄诗淇、刘雨欣）→ 据此补了 `passed_but_no_score` 规则。

### 踩坑记录
- openpyxl `read_only=True` 下 **不支持 `ws.cell()` 随机访问**，表头必须走同一次 `iter_rows` 遍历；`HashableWorksheet.title` 而非 `.name`。
- 证件号是 18 位数字，**绝不能做数值规范化**（float 精度丢失会让不同人撞成同一个键）→ 数值规范化仅对长度 ≤ 15 的字符串启用。
- 重复灌库时 `diff_events.from_version_id` 指向上一期，级联删不到 → 必须先显式清理引用再删版本。
- simulate 若不过口径过滤（require_identity），会导致 ground truth 与实际入库行数错位（曾出现 909 vs 887）。
